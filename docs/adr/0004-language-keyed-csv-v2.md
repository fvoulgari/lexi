# Language-keyed CSV v2 for every Collection

Collection-scoped CSV export uses a versioned format whose text and grammar columns are named by language ID (`text_en`, `grammar_el`, and so on), rather than by position in a pair. Each row carries the Collection pair, the card's own language IDs, `entry_id`, and Collection identity. Import maps texts and grammar by those IDs, validates that both required texts are present and that the card and Collection pairs match the destination, and accepts reversed pair order. Italian/Greek storage columns remain the canonical compatibility slots; no new per-language database columns are introduced.

`italian-notebook-v1` remains the aggregate library export format and remains importable, along with unversioned files and the legacy `type`, `unit`, `plural`, `example` and `gender` aliases. Version markers, JSON tags, reversible spreadsheet escaping, Unicode fidelity, 1 MiB / 2000-row bounds, and preview-before-confirm are unchanged. Unknown versions, missing texts, conflicting aliases, wrong-pair destinations, and grammar for a language outside the card are preview row errors, never silent positional guesses.

The Vocabulary workspace keeps its Italian/Greek defaults but accepts v2 files. The Collections workspace exposes import destinations for all owned collections, so non-legacy pairs such as `en/da`, `en/el`, `ja/en`, `ar/en` and `ja/ar` can be round-tripped with stable IDs and learning progress. The v2 header is derived from the language registry rather than a fixed list, so registry-only languages need no exporter or importer change. This is an exchange-format decision only: it does not migrate stored cards or publish a release.

Update (2026-11-25): Collection creation now opens the shared CSV dialog from every entry point. That dialog requires an explicit language pair from `/api/languages` and can create an empty collection without a CSV. The Italian/Greek defaults above remain for legacy card text slots and CSV files imported into an existing legacy collection; they are no longer defaults for a newly created collection's pair.

Update (2026-11-27): Collection-scoped v2 export is now scoped to the destination pair instead of emitting columns for every registered language. The importer still accepts the historical registry-wide v2 header because it reads columns by each card's explicit language IDs; identity, progress and reversed pair order remain unchanged. Two additions keep the same registry-driven columns: `lexi-simple-v1` maps `base`/`learning` texts onto the chosen Base/Learning orientation, and `italian-notebook-v3` adds `schema_version` plus a `metadata` cell holding the full structured grammar map. v3 rejects unknown metadata keys and unsupported schema versions instead of dropping them, so Danish fields without legacy columns survive losslessly. The import dialog now shows destination, recognised format and Base→Learning mapping before a shared preview/confirm validation; a new collection starts empty unless a source collection supplies its orientation. No v1 semantics or legacy direction IDs changed.
